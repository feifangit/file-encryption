# fileencrypt

[![CI](https://github.com/feifangit/file-encryption/actions/workflows/ci.yml/badge.svg)](https://github.com/feifangit/file-encryption/actions/workflows/ci.yml)

`fileencrypt` is a small batch encryption tool for directories. It recursively processes selected file types, preserves subdirectories, and turns each file into an independent, standard [age](https://age-encryption.org/) passphrase-encrypted file. Its built-in selection covers Markdown and common image formats, making it useful for ordinary folders of private documents and personal photos as well as Obsidian vaults.

[简体中文](docs/README.zh-CN.md)

```text
Documents/passport.jpg  -> Documents/passport.jpg.age
Notes/trip.md            -> Notes/trip.md.age
Public/...               -> can be excluded with .ageconfig
```

## How it works

- You enter one passphrase per batch, but age generates an independent salt, file key, and nonce for every file.
- Each target directory, including its subdirectories except paths excluded by `.ageconfig`, is treated as one passphrase domain. The tool expects all `.age` files in that scope to use the same passphrase.
- The output is standard age format with no custom header. Files can be decrypted by the official `age` CLI, the Go age library, and TypeScript `age-encryption`.
- The scrypt work factor is fixed at `14`. This is a performance tradeoff for large batches of small files and provides less resistance to offline passphrase guessing than age's higher default setting.
- File names, directory structure, original extensions, file counts, and approximate sizes remain visible.
- Encrypting the same plaintext twice produces different ciphertext.

Any one `.age` file gives an attacker enough information to guess the passphrase offline. A long passphrase generated by a password manager is still recommended. A short passphrase may prevent casual viewing, but it is not appropriate against a determined attacker.

## Use cases

Treat a directory as one consistently managed encryption scope when you want to:

- protect personal photos, scans, Markdown notes, or other selected file types in bulk;
- encrypt an existing directory once, then process only newly added files on later runs;
- preview exactly what will be processed, rotate the passphrase for the directory, or restore files in bulk;
- preserve the existing folder layout and file names while keeping every encrypted result in standard `.age` format.

For an ordinary directory, start with a backup, optionally create [`.ageconfig`](#directory-policy-ageconfig) at its root, and preview the plan before encrypting:

```bash
./fileencrypt preview ~/PrivateFiles
./fileencrypt encrypt ~/PrivateFiles
```

### Obsidian workflow

Obsidian vaults are an important use case, but not the tool's only purpose. To protect an existing vault for the first time, back it up, quit Obsidian completely, run `preview`, and then run `encrypt`.

After the initial batch, install the [Vault in Vault Obsidian plugin](https://github.com/feifangit/obsidian-vault-in-vault) to decrypt files on demand, edit or preview them normally, and encrypt them again from inside Obsidian. The Go tool and the plugin both read `.ageconfig` from the vault root and use compatible standard age passphrase-encrypted files, so they can share one file-selection policy and passphrase. Use the Go tool for initial batches, offline maintenance while Obsidian is closed, and passphrase rotation; use the plugin for day-to-day access in Obsidian.

## How this differs from the official `age` CLI

`fileencrypt` does not introduce a new encryption format and is not a replacement implementation of age. It uses the official Go age library and adds a directory-oriented workflow on top of standard age passphrase encryption.

| | Official `age` CLI | `fileencrypt` |
|---|---|---|
| Primary purpose | Encrypt or decrypt one input file or stream | Recursively process many files in a directory |
| Encryption modes | Passphrases, recipients, and identities | Deliberately limited to one-directory, one-passphrase workflows |
| File selection | The caller supplies each input | Extensions, `.ageconfig`, and command-line overrides select files |
| Obsidian behavior | No vault-specific rules | Protects Markdown and common images by default and skips `.obsidian` |
| Output and source | Writes to standard output by default or to `-o`; source management is left to the caller | Creates `original-name.age` automatically and removes the plaintext source only after the ciphertext is complete and verified |
| Batch passphrases | Each invocation is independent | Prompts once per operation and checks existing `.age` files for the same passphrase domain |
| Inspection and maintenance | Composed by the user or shell | Includes `preview`, concurrency, repeat-run handling, failure recovery, and `change-password` |

The resulting passphrase-encrypted files are interoperable. For example, the official CLI can still decrypt one file:

```bash
age -d note.md.age > note.md
```

For batch performance, `fileencrypt` fixes the scrypt work factor at `14`, below the default in the age library it uses. This is an explicit performance-over-hardening tradeoff. The tool links the Go library directly and does not invoke the system `age` executable, so `age` does not need to be installed at runtime.

## Install or build

With Go 1.25 or newer, install the current released version directly from source:

```bash
go install github.com/feifangit/file-encryption/cmd/fileencrypt@latest
```

Or build a checkout:

```bash
cd /path/to/fileencrypt
go build -o fileencrypt ./cmd/fileencrypt
```

Prebuilt macOS and Linux archives are attached to tagged [GitHub Releases](https://github.com/feifangit/file-encryption/releases). Windows is not currently supported because interactive passphrase input uses a Unix terminal.

The resulting `fileencrypt` binary is self-contained and does not require the `age` command to be installed. Release archives also contain checksums and third-party license notices.

## Default scope

Extension matching is case-insensitive. The built-in extensions are:

```text
.md
.avif .bmp .gif .jpeg .jpg .png .svg .webp
```

The tool always skips:

- every directory named `.obsidian` and its contents;
- the `.ageconfig` policy file;
- files already ending in `.age` during encryption;
- symbolic links, sockets, FIFOs, devices, and other special files;
- its own temporary files.

## Directory policy: `.ageconfig`

Place an optional hidden `.ageconfig` file at the root of the target directory:

```json
{
  "extensions": [".md", ".png", ".jpg", ".wav"],
  "exclude": ["Public", "Templates/daily.md", "attachments/shared"]
}
```

It defines the encryption scope and never stores a passphrase or key:

- `extensions` is optional. When omitted, the built-in defaults apply. When present, it must be a non-empty array. Extensions are normalized and deduplicated case-insensitively. `all`, `*`, `.age`, `.tar.gz`, and paths are not allowed.
- `exclude` is an optional array of paths relative to the target root. An entry can name a file or a directory; a directory entry excludes its entire subtree. The example excludes all of `Public`, one template file, and all of `attachments/shared`.
- Excluded paths are case-sensitive. Globs such as `*` and `?`, absolute paths, and `..` are not allowed. Excluding a plaintext path also excludes its corresponding `.age` file during decryption and passphrase rotation.
- Unknown JSON fields are rejected. `.ageconfig` itself is never encrypted.

If you only need exclusions, omit `extensions`:

```json
{
  "exclude": ["Public", "Templates"]
}
```

The built-in Markdown and common-image extensions still apply.

Policy precedence is:

```text
--ext  >  .ageconfig  >  built-in defaults
```

`--include` appends extensions to the final base policy. When `.ageconfig` exists, interactive `encrypt` displays its path, extensions, and excluded paths. Press Enter to accept the policy, or enter a replacement extension list for that run. `--ext` overrides only extensions; it does not edit the policy file, and `exclude` still applies.

An invalid `.ageconfig` stops the operation even when `--ext` is supplied. A malformed exclusion cannot therefore be bypassed silently by an extension override.

Interactive `encrypt` separates the policy prompt clearly:

```text
-------------------- ENCRYPTION POLICY --------------------
Policy source: .ageconfig (/Users/me/PrivateFiles/.ageconfig)
Files matching .jpg, .md, .png, .wav will be encrypted.
Excluded paths: Public, Templates/daily.md, attachments/shared
Press Enter to use this policy, or enter a replacement list (for example .md,.wav):
```

Press Enter to use the displayed policy. Entering `.md,.wav` replaces its extension selection for this run. Scripts can do the same with `--ext`:

```bash
./fileencrypt encrypt --ext .md,.wav ~/PrivateFiles
```

Use `--include` to add extensions to the policy, defaults, or `--ext` selection:

```bash
./fileencrypt encrypt --include .pdf,.canvas ~/PrivateFiles
```

Extension matching is case-insensitive. `encrypt --ext all` is deliberately rejected to avoid unintentionally encrypting programs, configuration, or unrelated files.

## Preview

`preview` only scans. It does not ask for a passphrase, modify files, or require confirmation:

```bash
./fileencrypt preview ~/PrivateFiles
./fileencrypt preview --ext .md,.wav ~/PrivateFiles
./fileencrypt preview --include .pdf ~/PrivateFiles
```

It reports the active policy source, counts and sizes by extension, and how many files would be encrypted or skipped:

```text
-------------------- PREVIEW --------------------
Directory: /Users/me/PrivateFiles
Policy source: .ageconfig (/Users/me/PrivateFiles/.ageconfig)
Selected file types: .jpg, .md, .png
Excluded paths: Public, Templates/daily.md, attachments/shared
-------------------- FILE TYPE STATISTICS --------------------
Type                  Files         Size    Encrypt       Skip
.age                     20      8.1 MiB          0         20
.jpg                       5     12.4 MiB          5          0
.md                      120      3.2 MiB        120          0
.pdf                       2      6.0 MiB          0          2
-------------------- SUMMARY --------------------
Would encrypt: 125 file(s), 15.6 MiB
Would skip: 22 scanned regular file(s), 14.1 MiB
Existing .age files: 20
Excluded from scan: 2 item(s)
```

`.obsidian`, `.ageconfig`, configured exclusions, symbolic links, and special files are counted separately under “Excluded from scan” rather than presented as ordinary scanned files.

Interactive terminals use color for headings, warnings, errors, and success messages. Color is disabled automatically when output is redirected, or explicitly with:

```bash
NO_COLOR=1 ./fileencrypt preview ~/PrivateFiles
```

## Encrypt

Close every program that may be editing the target directory. For an Obsidian vault, quit Obsidian completely:

```bash
./fileencrypt encrypt ~/PrivateFiles
```

The tool shows the number and total size of pending files, asks for confirmation, and then requests the passphrase. If the scope has no existing target `.age` file, a new passphrase must be entered twice. If `.age` files already exist, one is used to verify the passphrase before newly added files are encrypted.

Passphrase verification considers every non-excluded `.age` file in the target, not only extensions selected by the current `--ext`. For example, if the directory already contains `document.pdf.age` encrypted with “passphrase 1”, a later `encrypt --ext .jpg` run must also use “passphrase 1”. This prevents multiple passphrases from quietly appearing in the same policy scope. No new JPEG is encrypted if verification fails.

To use different passphrases, place the files in different directories and target each smaller directory separately, or use `exclude` to define a separate scope. Non-excluded `.age` files not created by this tool are also included in verification.

```text
-------------------- ENCRYPTION POLICY --------------------
Policy source: built-in defaults
Files matching .avif, .bmp, .gif, .jpeg, .jpg, .md, .png, .svg, .webp will be encrypted.
Press Enter to use this policy, or enter a replacement list (for example .md,.wav):
-------------------- PLAN --------------------
Encrypt: /Users/me/PrivateFiles
Policy source: built-in defaults
Selected original file types: .avif, .bmp, .gif, .jpeg, .jpg, .md, .png, .svg, .webp
Pending: 842 file(s), 516.2 MiB
Existing .age files: 0 (0 selected, 0 outside selection)
Warning: close applications that are editing this directory before continuing.
-------------------- CONFIRMATION --------------------
Proceed with encrypt? [y/N]: y
-------------------- PASSWORD --------------------
Create password:
Confirm password:
```

Running encryption again never creates `.age.age`. If there are no new matching files, the tool reports `Nothing to do.`

Skip the operation confirmation with:

```bash
./fileencrypt encrypt --yes --workers 4 ~/PrivateFiles
```

`--yes` never bypasses passphrase input or the weak-passphrase warning.

## Decrypt

```bash
./fileencrypt decrypt ~/PrivateFiles
```

The tool scans every non-excluded `.age` file. If it finds original extensions outside the active selection, such as a WAV previously encrypted with `--ext .wav`, it prompts explicitly:

```text
-------------------- ENCRYPTED FILE SELECTION --------------------
Policy source: built-in defaults
Selected original types: .avif, ..., .webp
Also found outside this selection: .pdf (2), .wav (5).
Press Enter to keep this selection, type 'all' for every non-excluded .age file, or enter a replacement list:
```

- Enter: decrypt only the currently selected types.
- `all`: decrypt every non-excluded `.age` file found in the directory.
- `.md,.wav`: replace the selection and decrypt only those types.

The non-interactive equivalents are:

```bash
./fileencrypt decrypt --ext all --yes ~/PrivateFiles
./fileencrypt decrypt --ext .md,.wav --yes ~/PrivateFiles
```

With `--yes`, the extension question is not shown. Unselected `.age` types are still reported and are never included implicitly.

`note.md.age` is restored as `note.md`. If an interrupted operation left both plaintext and ciphertext, the tool fully decrypts and compares them. Identical duplicates are cleaned up safely; different contents stop the operation without overwriting either file.

The official age CLI can also decrypt a single file:

```bash
age -d note.md.age > note.md
```

The official CLI restores the contents. `fileencrypt` also attempts to restore permissions and modification time from the `.age` file's filesystem metadata.

## Obsidian behavior after encryption

An Obsidian vault still opens because its directories and `.obsidian` settings remain unchanged. However, `note.md` becomes `note.md.age`, so Obsidian without a compatible plugin no longer treats it as a Markdown note. It disappears from the normal note list, Search, Graph, and Backlinks, and embeds of encrypted images stop working. This is not a decryption error; Obsidian does not recognize `.age` files by default.

Use the [Vault in Vault plugin](https://github.com/feifangit/obsidian-vault-in-vault) for on-demand access inside Obsidian.

## Change the passphrase

```bash
./fileencrypt change-password ~/PrivateFiles
```

The tool asks for the old and new passphrases. Each file is streamed directly from the old age decryption to the new age encryption; plaintext is not written as a normal intermediate file.

`change-password` also asks whether to include `.age` files outside the active extension selection. If WAV, PDF, or other non-default types were encrypted previously, selecting `all` is usually appropriate so the directory does not end up with two passphrases. Scripts can use `change-password --ext all`.

If rotation is interrupted, some files may use the new passphrase while the rest still use the old one. Run the command again with the same old and new passphrases to skip migrated files and continue.

## Safety and failure recovery

- Each destination is written to a temporary file in the same directory, fully authenticated, closed, and synced before it is published.
- The source is removed only after the destination is published. A sudden power loss may leave both plaintext and ciphertext, but the tool does not intentionally delete the only copy first.
- A later run recognizes and handles matching plaintext/ciphertext pairs.
- If the destination path already contains different data, the operation stops without overwriting it.
- Only one `fileencrypt` operation can run against the same directory at a time.
- If another program changes a source file during processing, the source is retained and the failure is reported.
- Owner, ACLs, extended attributes, hard-link relationships, and sparse-file layout are not preserved.
- The tool does not clean application caches, backup history, cloud version history, or Obsidian metadata stored outside the vault.

## Tests

```bash
go test ./...
go test -race ./...
go test -run '^$' -bench BenchmarkStatedWorkload -benchtime=1x ./internal/crypttool
```

Tests cover Unicode paths, nested directories, every default extension, `.ageconfig` extensions and file/directory exclusions, policy precedence, read-only Preview statistics, `.obsidian` exclusion, symbolic links, repeat encryption, wrong passphrases, corrupted ciphertext, standard age compatibility, decryption with the official `age` command, passphrase rotation, and interrupted-operation recovery.

The benchmark creates and encrypts 900 Markdown files of 100 KiB and 100 images of 5 MiB, for approximately 588 MiB total. It consumes significant CPU, memory, and temporary disk space.

During development, an Apple M5 Pro with the default four workers completed it in approximately `11.43 s` at `53.9 MB/s`. The measurement includes test-file creation and is only an order-of-magnitude reference; disk, CPU, filesystem, and worker count all affect the result.
